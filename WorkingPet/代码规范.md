# WorkingPet 代码规范

本文档总结当前代码库里 **已经在用** 的编码约定，新增代码应遵循这些约定以保持风格一致。仅 Windows 平台运行（大量代码直接用 `ctypes.windll` / `win32gui` 等 Windows-only API，不需要做跨平台兼容）。

## 1. 模块职责划分

| 模块 | 职责 | 原则 |
|---|---|---|
| `manei_manager.py` | 入口 + 所有 UI（`QWidget`/`QDialog`）+ 状态机 | UI 逻辑集中在这里，不要把 UI 代码拆到别的模块 |
| `work_log.py` | 工作日志的读写 + 豆包文本 API 封装 + prompt 拼装 | 纯逻辑，不依赖 PyQt，可独立于 UI 测试/复用 |
| `context_collector.py` | 音乐/中文输入/截图上下文采集 | 面向「AI 需要的上下文」，产出可直接拼进 prompt 的文字 |
| `data_collector.py` | 聊天/OCR/应用时长/鼠标/浏览器历史采集 | 面向「原始行为数据落盘」，暂不直接进 prompt |

新增功能先想清楚属于哪一层：**纯数据/AI逻辑** 放 `work_log.py` 式的模块，**后台采集** 放 `context_collector.py` / `data_collector.py` 式的模块，**UI 交互** 才写进 `manei_manager.py`。

## 2. 命名约定

- 类名 `PascalCase`：`DesktopPet`、`BubbleWidget`、`ContextCollector`。
- 函数/变量 `snake_case`。
- 模块内部、不希望被外部直接调用的函数/方法一律加前缀下划线：`_doubao_request`、`_get_state`、`_save_chat_entry`。真正对外的入口不加下划线，例如 `ContextCollector.start_all()` / `get_context_snapshot()`、`data_collector.start_all()`、`work_log.add_log()`。
- 常量全大写：`LOG_FILE`、`MAX_ENTRIES`、`_CHAT_KEYWORDS`。
- 每个采集类内部统一用 `MAX_*` 常量控制保留条数（如 `InputCollector.MAX_ENTRIES = 50`），避免日志文件无限增长。

## 3. 文件结构与分节注释

- 每个文件顶部用三引号 docstring 简要说明「这个文件采集/负责什么」，`data_collector.py` / `context_collector.py` 是范例。
- 文件内用 `# ══════...` 或 `# ── 标题 ──...` 分隔不同职责的代码块（参考 `context_collector.py` 里「1. 中文键盘输入采集」「2. 网易云音乐当前歌名」「3. 桌面截图 + 豆包视觉分析」的分节方式）。新增一个采集器/一类功能时，照此加一个新分节，不要混杂在无关代码中间。

## 4. 配置与数据持久化模式

- 统一走「JSON 文件 + 顶层 `load_xxx()`/`save_xxx()` 函数」模式，不引入数据库：
  - `manei_manager.py`: `load_config()` / `save_config()`
  - `work_log.py`: `load_logs()` / `save_logs()`
  - `data_collector.py`: 通用 `_read_json(path, default)` / `_write_json(path, data)` 辅助函数
  - `context_collector.py` 里每个采集类各自维护 `_load()` / `_save()`
- 新增一类需要落盘的数据，优先复用 `_read_json`/`_write_json` 这种「读全量 → 改内存 → 写全量」模式，除非数据量大到需要考虑性能。
- 所有运行期产出的数据文件（工作记录、聊天记录、浏览历史、`config.json` 等）**禁止提交到 git**，已在 `.gitignore` 中列出。新增采集器产出的文件也要同步加入 `.gitignore`。
- **`config.json` 严禁包含真实密钥提交到仓库**；`config.example.json` 作为模板维护，字段变化时两个文件都要更新。

## 5. 跨线程通信

- 所有耗时操作（AI 请求、截图分析、网络请求、文件 I/O 较重的采集）必须放进 `threading.Thread(daemon=True)`，不能阻塞 Qt 主线程。
- **绝不能在子线程里直接操作 Qt 控件**。子线程 → 主线程的结果传递统一走 `Bridge`（`QObject` + `pyqtSignal`）模式：在 `Bridge` 上定义信号，主线程 `connect()` 处理槽函数，子线程里 `self.bridge.xxx.emit(...)`。参考 `manei_manager.py` 的 `Bridge` 类和 `_on_user_input()` 的用法。
- 后台采集器（`context_collector.py` / `data_collector.py`）里的线程不需要 `Bridge`，因为它们只落盘、不直接更新 UI；只有需要把结果显示到界面上的操作才需要 `Bridge`。

## 6. 错误处理

- 两种不同的容错级别，按场景选择：
  - **后台采集/后台任务**：静默失败，`except Exception: pass`（可选择性地设默认值），保证单个采集器出错不影响主程序或其他采集器。这是 `data_collector.py` 和 `context_collector.py` 的一贯做法（`start_all()` 逐个用 `try/except` 包裹调用）。
  - **用户主动触发的操作**（对话、生成周报/日报）：捕获异常后要把出错信息通过 `Bridge` 回传，用气泡提示用户，例如 `self.bridge.reply_ready.emit(f"出错了：{e}", False)`，不能静默吞掉。
- 不要用裸 `except:`，统一 `except Exception:`。

## 7. AI（豆包）调用约定

- 端点、鉴权方式固定：`https://ark.cn-beijing.volces.com/api/v3/chat/completions`，`Authorization: Bearer <api_key>`，`model` 字段填 `endpoint_id`。
- 纯文本请求复用 `work_log._doubao_request(api_key, endpoint_id, messages, max_tokens)`，不要在别处重复拼 `urllib.request` 逻辑；视觉（截图）请求目前在 `manei_manager.analyze_screenshot()` 和 `context_collector.ScreenshotCollector._take_and_analyze()` 里各自实现了一份类似逻辑，如果后续要新增第三处视觉调用，应先把这两处合并成一个共享的 `analyze_image()` 工具函数再复用，不要再复制第三份。
- 要求 AI 返回 JSON 时（如 `understand_intent`），prompt 末尾明确写「只返回JSON，不要任何解释」，解析前用 `.replace("```json", "").replace("```", "")` 去掉可能的 Markdown 代码块包裹。
- prompt 用 f-string 拼接，中文提示词，明确给格式示例和字数/条数限制（例如日报草稿「最多8条」），减少 AI 输出跑偏。

## 8. GIF / 状态相关

- 当前实现里 GIF 文件名直接以字符串字面量出现在 `_get_state()` 里（如 `"angry.gif"`），**没有** `GIF_*` 常量层。新增一个状态：
  1. 把 GIF 素材放到项目根目录
  2. 在 `_get_state()` 里按优先级插入判断分支，返回 `(文件名, 状态文案)`
  3. 如果同一优先级位置有多个互斥状态，注意判断顺序——`_get_state()` 是按 if/elif 顺序短路的，越靠前优先级越高
- `switch_gif(filename, force=False)` 内部按原始 GIF 宽高比自动缩放到 `pet_size`，不需要手动算比例。

## 9. Qt 组件约定

- 自定义顶层小部件（气泡、输入框）统一设置 `FramelessWindowHint | WindowStaysOnTopHint | Tool` + `WA_TranslucentBackground`，样式用内联 `setStyleSheet()` QSS，字体固定 `Microsoft YaHei, Arial`。
- 子窗口（`ChatInput`/`BubbleWidget`）位置跟随主窗口，统一在 `_update_child_positions()` 里计算，主窗口 `moveEvent()` 里调用它，不要在别处单独 `move()`。
- 用户输入 → 業務逻辑的信号命名统一用「过去分词」表达完成态：`submitted`、`open_dingtalk_clicked`、`daily_draft_ready`。

## 10. 新增设置项的流程

1. `DesktopPet.__init__` 里从 `cfg.get(...)` 读默认值
2. `SettingsDialog.__init__` 里加一个 `QLineEdit` 输入框和 `layout.addRow(...)`
3. `SettingsDialog.save()` 里读取输入框、赋值回 `self.parent.xxx`，并加进 `save_config({...})` 的字典
4. 如果这个设置会影响 GIF 显示（比如 `pet_size`），`save()` 末尾已经统一调用了 `switch_gif(force=True)` 刷新，不需要额外处理

## 11. 隐私与安全边界（重要）

- `data_collector.py` 涉及聊天内容剪贴板劫持、屏幕 OCR、浏览器历史读取，这类采集**只能用于本机个人用途**，不允许：
  - 把采集到的原始数据（`chat_input_log.json` / `ocr_log.json` / `browser_history.json` 等）提交到 git 或上传到任何远端服务
  - 把这些数据发给非用户本人配置的第三方 API
- 截图相关的采集（`context_collector.ScreenshotCollector` / `manei_manager.analyze_screenshot`）设计上**只保留 AI 生成的文字描述，不落盘保存截图本身**，新增截图相关功能要延续这个原则。
- 任何新增的 API Key / Token 一律只写进本地 `config.json`（已 gitignore），`config.example.json` 里对应字段留空字符串。

## 12. 暂无的工程设施（如需补充请遵循以下约定）

- 目前没有自动化测试。如果要加测试，建议新建 `tests/` 目录，不要把一次性调试脚本（例如已删除的 `debug_import.py`）留在仓库根目录。
- 没有 lint/format 配置；保持现有的 4 空格缩进、双引号字符串为主的风格，函数间空一行、类间空两行。
